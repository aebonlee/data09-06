## 결정과 이유

- **열 배치를 고를 수 있게 했습니다.** 기획서 10장 3번대로 Testlab Neo 내보내기가 세로형인지 가로형인지 확인되지 않았습니다. 세 가지 배치(세로형: 한 행에 RPM·채널·방향·단위·주파수·응답 / 가로형: 한 행이 한 RPM, 주파수가 열 제목 / 가로형 열=RPM: 한 행이 한 주파수)를 두고, 열 제목으로 짐작해 채운 뒤 사용자가 고치게 했습니다. 같은 열 제목의 파일을 다시 올리면 지난 매핑을 그대로 씁니다.
- **Testlab 머리 정보 줄을 건너뜁니다.** 아래 줄이 대부분 숫자인 첫 줄을 머리행으로 짐작하고, 줄 번호를 직접 고칠 수도 있습니다.
- **유럽식 숫자(세미콜론 구분·소수점 쉼표)** 를 선택할 수 있게 했습니다. 측정 장비 PC 의 지역 설정에 따라 내보내기 형식이 바뀌는 경우에 대비한 것입니다.
- **형식 검사는 건너뛰고 기록합니다.** 빈 값·숫자 아님·RPM 0 이하(오더 계산 불가)·음수 주파수 행은 빼고, 중복 주파수·중복 RPM 은 처음 값만 쓰며, 음수 응답·같은 채널 안 단위 불일치는 경고만 합니다. 모두 원본 줄 번호와 함께 경고 로그에 남고 CSV 로 저장됩니다.

- **피크는 국소 최대값**(양옆 이웃보다 크거나 같고 한쪽보다는 큰 칸)으로 잡고, RPM 별로 큰 순서 N개를 냅니다. 스펙트럼 양 끝 칸은 이웃 하나보다 클 때만 피크로 봅니다. 평평한 구간은 피크가 아닙니다.
- **그래프는 직접 그렸습니다(SVG·canvas).** 기획서는 Plotly.js 등을 예로 들었지만 3MB 이상의 라이브러리 없이도 1단계 그래프 두 종과 툴팁을 만들 수 있어 오프라인·file:// 사용을 단순하게 유지했습니다. 제출자 초안이 특정 라이브러리를 쓴다면 맞춰 바꿀 수 있습니다.

## 실제 입력 형식 (이제 확인됨)

- UTF-8 **BOM**, 쉼표 구분, 소수점은 점, 작은 값은 `7.05E-05` 같은 지수 표기, 줄 끝 CRLF.
- 1줄 `Curve 1,,,,` → 빈 줄 → `MS Logging` (→ 30B 는 `InputGUID`·`RecentGUID` 도) → `Standard\All\…` 머리 정보 줄들(**0열이 항목 이름, 1열부터 Curve 하나당 한 열**) → 빈 줄 → 단위 줄(`Hz,g,g,…,Pa`) → 표시 척도 줄(`Linear,Log (RMS),…,dB`) → 데이터.
- 데이터: **0열 = 모든 Curve 공통 주파수(Hz)**, 1열부터 Curve별 진폭. 130B 는 끝에 `,,,,` 만 있는 줄이 약 8천 줄 붙어 있습니다.
- RPM 은 열이 아니라 **`Dataset name`** 에 글자로 들어 있습니다: `rpm  2000`(130B), `closed (397.00s-399.00s)RPM2000_Report to Excel`(30B). `Original run` 은 실제 측정 RPM(`rpm  2002`)이지만 v34 는 Dataset name(공칭 RPM)을 씁니다 — 우리도 같게.
- 위치·방향은 **`DOF id`** (`LL:+X`), 소음 채널은 `out`·`Pump` 처럼 방향이 없습니다. 단위는 `Y axis unit`(g·Pa).
- 표시 척도 줄의 `Log (RMS)` 는 표시 방식일 뿐 값은 선형이고, **`dB` 인 열(소음 Pa 채널)은 값이 이미 dB** 입니다(기준 20 µPa, 12~60 dB 범위).
- 파일 이름 `36,45order` · `39order` 가 관심 오더를 가리킵니다.

| 항목 | v34 | 1차 도구 | 이번 |
|---|---|---|---|
| 오더 식 | 이론 주파수 = 오더 × RPM / 60 | 오더 = 주파수 × 60 / (RPM × 회전비) | 같은 식(회전비 1 = v34) |
| 대역 | 이론 주파수 ± 검색 범위 **Hz**, 그 안 최대 칸이 피크 | ± 반폭 **오더** 대역 전체 | v34 방식이 기본 |
| 오더 진폭 | 검출 피크 ± 합산 범위 Hz 칸의 RSS (dB 원본은 에너지 합) | 대역 최대값 또는 대역 RSS | v34 방식 |
| 피크 동점 | 먼저 나온(낮은 주파수) 칸 | — | 같음(`>` 비교) |
| 범위 밖 | 이론 주파수가 범위 밖이어도 창이 걸치면 값을 내고 「불일치」 | 대역에 칸이 없으면 빈칸 | v34 와 같음 |
| dB 입력 | 소음 dB → Pa 로 바꿔 둠, 진동 dB 는 합산 때 에너지로 더함 | 처리 없음(선형 가정) | 모두 기준값으로 선형으로 바꾼 뒤 RSS — 수식상 v34 와 같은 값 |
| dBA 입력 | 원본 dBA 는 가중을 빼서 Pa 로 | — | 같음. 단 dBA 원본을 dBA 로 다시 볼 때 v34 는 합산값에 피크 주파수 가중을 되돌리고, 우리는 칸마다 가중을 뺀 뒤 피크 주파수 가중을 더함 — 합산 범위 ±1 Hz 에서 차이는 무시할 수준(실제 파일에 dBA 원본 없음) |

맞대기 결과: **실제 파일 2종 + 합성 예시 × 모든 채널 × 설정 3가지(검색/합산 ±1/±1 dB, 0/0 선형, ±3/±2 dBA)** 에서 v34 함수(`test/v34-harness.mjs` 가 `docs/source/order_analysis_v34.html` 의 계산 함수를 그대로 꺼내 실행)와 검출 피크 주파수·합산 칸 수·판정이 모두 같고, 오더 진폭·표시값·RSS 합산이 1e-9(상대)·1e-7 dB 안에서 같습니다.

### v34 에서 본 결함·주의점 (따르지 않거나 적어 둠)

- **DOF id 끝 글자 방향 해석**: v34 는 `:` 가 없어도 이름 끝이 X·Y·Z 면 방향으로 잘라 냅니다(예: 소음 채널 이름이 「Box」 면 위치 「Bo」). 이 도구는 `:` 가 있을 때만 방향으로 봅니다. 실제 두 파일에서는 결과가 같습니다.
- **같은 위치·방향·RPM Curve 중복**: v34 는 오류를 적고 **나중 Curve** 로 덮어씁니다. 이 도구는 경고하고 처음 것을 씁니다.
- **주파수 간격보다 좁은 검색 범위**: v34 는 칸을 못 찾아 값이 빕니다. 이 도구는 경고를 따로 적고, 불러올 때 간격이 검색 범위의 두 배보다 넓으면 검색 범위를 간격의 절반으로 넓힙니다(정보 로그, 설정에서 되돌릴 수 있음). 실제 파일(1 Hz 간격)은 해당 없음 — 1차 가상 예시(4 Hz 간격)에서만 동작합니다.
- 오더 0 을 v34 는 받습니다(이론 주파수 0 Hz). 이 도구는 0 이하 오더를 뺍니다.

## 기여도 정의 (v40 에 없어 표준 정의)

v40 에 overall·기여도·contribution 이라는 말이 한 번도 나오지 않습니다(`grep` 0건). 그래서 오더 분석에서 흔히 쓰는 에너지 비율로 정했습니다.

- **Overall** = RPM 마다 Overall 범위(설정, 빈칸 = 측정 범위 전체) 칸들의 제곱합의 제곱근. `overallOf`
- **오더 기여도(%)** = 오더 에너지 ÷ Overall 에너지 × 100, 에너지 = 진폭². 오더 에너지 = v34 오더 진폭²(= 검출 피크 ± 합산 범위 칸들의 제곱합). `contributions`
- **기타(오더 외)** = 100 − 오더 기여도 합. 오더 중 하나라도 값이 없으면 합·기타는 비움.
- dB 표시여도 기여도는 같은 에너지 비율(Overall 만 dB 로 표시). **dBA** 는 칸마다 A-가중한 에너지로 나누고 오더는 검출 피크 주파수 가중 — v34 오더 RSS 합산 dBA 와 같은 규칙.
- 창 함수 보정은 분자·분모에 같이 붙어 비율에 영향이 없음. Overall 절댓값에는 보정 없음(Testlab 칸 값 그대로).
- **합이 100 을 넘는 경우를 막지 않고 알립니다**: 오더끼리 합산 창이 겹치면(같은 칸이 두 번) 또는 오더 창이 Overall 범위 밖으로 나가면 경고 로그 + 막대 위 빨간 「!」 + 표 「확인」 열.

제출자에게 이 정의가 맞는지(진폭 비율·dB 차가 아닌지), Overall 범위를 전체로 둘지 확인을 부탁했습니다(기획서 10장).
